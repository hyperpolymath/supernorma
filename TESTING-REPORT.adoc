== History: why the suite never ran under Deno

Two independent, structural problems, both now resolved by the move to Bun:

1. **Missing `@rescript/runtime` resolution.** ReScript 12's built-in stdlib
   compiles to imports from the `@rescript/runtime` npm package. Deno had no
   `imports` map entry for it, so any generated `.res.js` file failed at
   load time with `Import "@rescript/runtime/..." not a dependency and not
   in import map`. Bun resolves npm-style bare specifiers natively via
   `node_modules` (populated by `bun install`, using `rescript` as a real
   `package.json` devDependency) — no import map needed.
2. **Test file discovery.** ReScript's `suffix` setting always appends
   `.res.js` verbatim to compiled output (e.g. `Config_test.res.js`), so
   generated test files can never end in `_test.js`/`.test.js` the way both
   Deno's and Bun's default test-discovery conventions require. `bun test`
   still applies this convention to bare/directory arguments, but treats
   explicit `./`-prefixed file paths as literal — `package.json`'s `test`
   scripts build that file list via `find`. See
   `.github/workflows/rescript-bun-ci.yml` for the same logic in CI.

== How to run

[source,bash]
----
bun install       # install rescript + resolve @rescript/runtime
bun run build      # compile ReScript -> *.res.js
bun run test       # run the full suite
bun run test:unit
bun run test:integration
----

Record real pass/fail counts here after each run; do not update this report
without running the suite.
